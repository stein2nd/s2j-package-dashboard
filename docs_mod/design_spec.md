# S2J Package Dashboard - 設計/ブランディング仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、設計およびブランディングを定義します。

アプリケーション・アイコン、ロゴ、カラーパレット、具体的なコンポーネント設計等については、プロトタイプおよび実機検証を通じて段階的に確定します。

## 目的

本ドキュメントでは、S2J Package Dashboard の視覚設計、ブランド、UI 設計、情報表現および設計上の基本原則を定義します。機能仕様およびアーキテクチャー仕様とは分離します。

## 非目的

下記は、本仕様の目的としません。

* Packagist 公式アプリケーションの UI 再現
* GitHub 公式アプリケーションの UI 再現
* 「ブランド色」を多用した、ビジュアル設計
* 過度なアニメーション
* 情報量を増やすこと自体を目的とした、ダッシュボード
* KPI を単一のスコアに、過度に集約すること
* プラットフォーム間で、UI を完全に同一化すること

## 責務

ブランド表現、情報設計、色/タイポグラフィ、統計の視覚表現、設計品質チェックリストを定義します。

## 非責務

Viewport 整合性は [`ui-viewport.md`](./ui-viewport.md)、画面構成は [`screen_spec.md`](./screen_spec.md)、ナビゲーション挙動は [`navigation_spec.md`](./navigation_spec.md)、横断 UI 振る舞いは [`ui.md`](./ui.md)、認証方針は [`authentication_spec.md`](./authentication_spec.md) を正本とします。UI String の Hard-code 禁止と両言語での操作可能性は [`ui.md`](./ui.md) を正本とします。指標の意味、Chart 種類、派生の定義は [`statistics_spec.md`](./statistics_spec.md) を正本とします。

## 設計哲学

S2J Package Dashboard は、Composer パッケージを日常的に利用/開発/メンテナンスする開発者向けの開発者ツールです。

設計は、下記を基本理念とします。

1. **「情報」ファースト**

   * 装飾よりも、情報の可読性を優先する。

2. **開発者志向**

   * 開発者が必要とする情報を、過度な説明なしに理解できる。

3. **ネイティブ体験**

   * 各プラットフォームの、標準的な操作体系を尊重する。

4. **データ駆動**

   * パッケージ/リポジトリの状態を数値、時系列、チャートによって把握できる。

5. **控えめなブランディング**

   * ブランド表現を強調しすぎず、パッケージ情報そのものを主役とする。

6. **安定したレイアウト**

   * 起動、回転、Viewport 変更等によって、視覚的な不安定さを生じさせない。

7. **デフォルトでアクセシブル**

   * 色、文字サイズ、コントラスト、操作領域等について、アクセシビリティを考慮する。

## ブランド・アイデンティティ (ID)

### 1. 製品名

アプリケーション内で「S2J」を省略する場合でも、App Store 等の正式な製品名称は、「S2J Package Dashboard」とします。

* 正式名称: **S2J Package Dashboard**
* 短縮名称: **Package Dashboard**

## ブランド・ポジショニング

S2J Package Dashboard は、Composer パッケージ、開発者履歴、ダッシュボードの3つの概念を組み合わせた開発者ツールとして位置付けます。

下記は、主な情報源です。Packagist (パッケージ / バージョン数 / 依存関係 / ダウンロード統計) と GitHub (リポジトリ / 履歴 / スター数 / Issue 数 / プル・リクエスト数 / リリース数) を、一つの開発者志向ダッシュボードとして統合します。

## ブランド・パーソナリティ

ブランドの印象は、下記を基本とします。「開発者向けツール」であることを明確にしつつ、過度に無機質な管理ツールにならないバランスを目指します。

| 属性 | 方針 |
| --- | --- |
| プロフェッショナル | 高い |
| 技術的 | 高い |
| 落ち着いた | 高い |
| 情報豊富 | 高い |
| ミニマル | 高い |
| 遊び心 | 低い |
| 装飾的 | 低い |
| 宣伝的 | 低い |

## ロゴ/アプリケーション・アイコン

### 1. 基本方針

アプリケーション・アイコンおよびロゴは、下記のいずれかを想起できる単純な形状を基本とします。小さなサイズでも識別可能であることを優先します。

* S2J
* パッケージ
* ダッシュボード
* 接続/集約

### 2. アプリケーション・アイコン

アプリケーション・アイコンは、「パッケージ・ダッシュボード」そのものを象徴する、独自のシンボルを基本とします。

アプリケーション・アイコンは、細かな文字や複雑な図形を使用しません。特に下記を避けます。

* 小さな「Packagist」文字列
* 小さな GitHub ロゴの複数配置
* 細すぎる線
* 多数の色
* 複雑なグラフ

### 3. サードパーティのロゴ

Packagist および GitHub のロゴ・サービスアイコンは、本アプリケーションのブランド・ロゴと混同されないようにします。

サードパーティ・サービスのロゴを、アプリケーション・アイコンの主要な構成要素として使用しません。

サービス名やロゴを使用する場合は、それぞれのブランド・ガイドラインに従います。

## 色の設計

### 1. 基本原則

色は、ブランド表現よりも、情報状態の伝達を優先します。

基本 UI は、iOS/iPadOS の「システムカラー」および「意味論的な配色」を優先します。

固定 RGB 値を、過度に使用しません。

### 2. 意味論的な配色

状態を、色だけで表現してはなりません。アクセシビリティ上の「色だけに依存しない」振る舞いは [`ui.md`](./ui.md) も参照します。

たとえば、

* 🟢 アクティブ
* 🟡 警告
* 🔴 エラー

上記のような色を表現する場合でも、下記を併用します。

* ラベル
* アイコン
* 形状
* 状態テキスト

### 3. ダークモード

ライトモードおよびダークモードの双方を、正式にサポートします。

色の設計は、固定背景色ではなく、可能な限り「意味論的な配色」を利用します。

下記を確認します。

* テキストのコントラスト
* 補助テキスト
* チャート
* バッジ
* 区切り線
* カード
* ナビゲーション
* エラー/警告/成功

## タイポグラフィ

iOS/iPadOS では、プラットフォーム標準の「San Francisco」系フォントを基本とします。

固定フォントサイズを過度に使用せず、「ダイナミック・タイプ」を考慮します。

情報階層には、下記のような「意味論的タイポグラフィ」を利用します。

* 大きなタイトル
* タイトル
* 見出し
* 本文
* 注記
* 小見出し
* 脚注
* キャプション

パッケージ名/バージョン/統計等では、情報の重要度に応じて「タイポグラフィの階層」を設定します。

## 情報の階層

画面上の提示順は [`screen_spec.md`](./screen_spec.md) の Dashboard / Package Detail を正本とする。本仕様は、その順にタイポグラフィ階層を対応させることだけを定める。

## ナビゲーション・モデル

行き先は [`navigation_spec.md`](./navigation_spec.md)、画面の情報カテゴリーは [`screen_spec.md`](./screen_spec.md) を正本とする。本仕様は、UI ウィジェットがプラットフォームで変わってよいこと、情報カテゴリーそのものは変えないことだけを定める。

## マイ・パッケージ

「マイ・パッケージ」は、ユーザー自身がメンテナンスするパッケージを表示します。視覚的には、「お気に入り」と区別可能にします。

パッケージの所有者であることを過度に強調せず、「自分が管理するパッケージ」であることが自然に理解できる UI とします。画面上のリスト構成は [`screen_spec.md`](./screen_spec.md) を正本とします。本仕様は、Maintained を Favorite と視覚的に区別することだけを定めます。

## お気に入り

「お気に入り」は、ユーザーが任意に登録したパッケージを表示します。視覚的には、「マイ・パッケージ」とは、明確に区別します。

「お気に入り」には、星形等の一般的な視覚表現を使用してかまいません。ただし、GitHub スター等の外部サービスの指標と混同しないようにします。Maintained との意味の区別は [`domain_rules.md`](./domain_rules.md) を正本とします。

## パッケージ・アイデンティティ (ID)

パッケージ名は、画面上で最も重要な識別情報の一つとして扱います。Composer パッケージの完全修飾名 `vendor/package` を基本表示とします。省略表示によってパッケージの一意性を失いません。

たとえば、`@s2j/docs-linter` のような npm 固有の表現を Composer パッケージに使用しません。Composer では、`stein2nd/docs-linter` のようなパッケージ名を使用します。

## バージョン設計

バージョンは、パッケージ名に次ぐ重要情報として扱います。

安定したバージョンを基本表示し、`1.0.22` のように明確に表示します。先行リリースについては、下記のような原表記を保持します。

* 1.1.0-beta.1
* 1.1.0-RC1

バージョンを、色だけで区別しません。

## 依存関係の設計

依存関係は、パッケージとの関係性が理解できるように表示します。依存関係が大量に存在する場合は、検索/フィルター/折りたたみ等によって、情報密度を制御します。

基本形式は、下記とします。

```text
symfony/console
^7.0
```

必要に応じて、下記を区別します。

* `require`
* `require-dev`
* `suggest`
* `conflict`
* `replace`
* `provide`

## 統計の設計

重要な指標は、チャートより先に概要値として提示します。指標の意味・出典・期間は [`statistics_spec.md`](./statistics_spec.md)、画面上の置き場所は [`screen_spec.md`](./screen_spec.md) を正本とします。

本仕様は、概要値をチャートより先に見せること、時系列を折れ線等で示すこと、現在値 / 期間 / 単位 / 出典を視覚上省略しないことだけを定めます。複数ソースを単一の「人気度」に統合しないことは [`statistics_spec.md`](./statistics_spec.md) を正本とします。

## 派生指標

派生の定義は [`statistics_spec.md`](./statistics_spec.md) を正本とします。本仕様は、公式指標と派生を視覚上区別し、計算根拠へたどれることだけを定めます。

## チャート

Chart の種類と Gap / 補間の意味は [`statistics_spec.md`](./statistics_spec.md)、色だけで伝えないことは [`ui.md`](./ui.md) を正本とします。本仕様は、系列を必要最小限にし、凡例は省略可、ツールチップで正確値を確認でき、時間軸と単位を明確にする視覚だけを定めます。

## 「空」の状態

Empty の振る舞い (説明と次アクション) は [`ui.md`](./ui.md) を正本とする。本仕様は、データがないときに空白画面へ落とさない視覚だけを定める。

## 「ロード中」状態

スケルトンの使い方は [`ui.md`](./ui.md) を正本とする。起動時や向き変更時の Layout ズレ禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とする。

## 「エラー」状態

エラー UI の振る舞い (理解可能な文、再試行) は [`ui.md`](./ui.md) を正本とする。本仕様は、エラーを通常のパッケージ・メタデータと視覚的に区別することだけを定める。

技術的な「エラーコード」等は、必要に応じて詳細情報として提示します。

## 認証 UI

認証を公開情報の閲覧障壁にしない方針は [`authentication_spec.md`](./authentication_spec.md)、導線は [`ux_flows_spec.md`](./ux_flows_spec.md) を正本とする。本仕様は、起動直後に認証入力を求めない見た目と、「Packagist パスワード」フォームを基本 UI にしないことだけを定める。

Token を使用する場合は、用途と必要権限を説明します。

## セキュリティ重視の UI

Token / クレデンシャルを README、パッケージ詳細、ログ、アナリティクス、スクリーンショット、共有シートへ出さないことは [`security_spec.md`](./security_spec.md) を正本とする。本仕様は、Secret を通常のパッケージ・メタデータと視覚的に区別することだけを定める。

## Viewport 整合性

到達可能性、レイアウト安定性、コンテンツ整合、操作整合の正本は [`ui-viewport.md`](./ui-viewport.md) とする。本仕様の品質チェックリストは、設計レビュー用の確認項目とする。

## 水平方向のコンテンツ

横方向に情報が収まらない場合の視覚的な選択肢は下記とする。到達可能性とオーバーフロー禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とする。

1. レイアウトを再構成する
2. 「タブ/セグメント」コントロール等に分割する
3. 「水平スクロール」を提供する
4. iPad では、「サイドバー/マルチカラム」レイアウトに変更する

## レスポンシブ設計

同一の情報モデルを利用しながら、Viewport に応じて「レイアウト」を変更します。「iPhone のレイアウトを拡大して、iPad に表示する」ことを基本設計としません。

iPhone / iPad / Android の画面構成は [`screen_spec.md`](./screen_spec.md)、ナビゲーション構造は [`navigation_spec.md`](./navigation_spec.md)、サイズクラスと到達可能性は [`ui-viewport.md`](./ui-viewport.md) を正本とする。

## 向き

「縦置き/横置き」の双方を、正式にサポートします。向き変更時の Layout / 到達可能性の要件は [`ui-viewport.md`](./ui-viewport.md) を正本とする。

## アクセシビリティ

アクセシビリティを「設計の後付け仕様」としません。支援技術と Chart Textual Summary の振る舞いは [`ui.md`](./ui.md)、コントラストの視覚基準は本仕様の色設計を正本とします。

## モーション

モーションは、「状態変化の理解」を補助する目的で、使用します。過剰なアニメーションを使用しません。「動きの低減」の振る舞いは [`ui.md`](./ui.md) を正本とします。起動・向き変更時の Layout 安定性は [`ui-viewport.md`](./ui-viewport.md) を正本とします。

特に、下記では、「レイアウトの安定性」をアニメーションより優先します。

* アプリケーションの起動
* 向き変更
* ウィンドウ・リサイズ
* タブの切り替え
* ナビゲーション
* データの更新

## ローカライズ

下記は、初期の対応言語です。

* 日本語
* 英語

表示文字列は、コードに直接埋め込みません。「翻訳可能な文字列」として管理します。Hard-code 禁止の UX 振る舞いは [`ui.md`](./ui.md) を正本とします。

特に下記をローカライズ対象とします。

* UI ラベル
* ボタン
* エラー・メッセージ
* 「空」の状態
* 統計 ラベル
* アクセシビリティ・ラベル
* ヘルプテキスト

パッケージ名、リポジトリ名、バージョン等の外部データは、原文を保持します。

## 日付/数値の書式設定

日時および数値は、ユーザーの「ロケール」に応じて表示します。

たとえば、下記のような「コンパクト記数法」表示を使用する場合でも、「詳細値」を確認できるようにします。

* `1,234`
* `1.2K`
* `1.2M`

下記のように、統計値には、(可能な限り) 単位を明示します。

* `2,478 downloads`
* `38 stars`
* `12 dependents`

## パッケージ・ソースのブランディング

Packagist および GitHub は、情報源として明確に区別します。

たとえば、下記のように、表示します。

```text
Packagist
ダウンロード数

GitHub
スター数
フォーク数
Issue 数
```

サードパーティ・サービスの「ブランド色」を、アプリケーション全体の「主色」として使用しません。

## 共有

パッケージ情報を共有する場合、共有される情報にクレデンシャル (資格情報) が含まれないことを保証します。

下記は、共有可能な情報です。

* パッケージ名
* パッケージ URL
* バージョン
* 公開統計
* GitHub リポジトリ URL

下記は、共有してはならない情報です。

* API Token
* OAuth Token
* 非公開リポジトリ情報
* 内部クレデンシャル (資格情報)
* デバッグ用 Secret

## スクリーンショット/マーケティング設計

App Store 等のスクリーンショットでは、「実際のアプリケーション」UI を基本とします。

スクリーンショット用に、「通常のアプリケーションでは存在しない」UI を作成してはなりません。

パッケージ名、統計値、リポジトリ情報等は、公開可能なデータまたはテスト用データを使用します。

クレデンシャル (資格情報) や非公開リポジトリ情報を、スクリーンショットに含めません。
