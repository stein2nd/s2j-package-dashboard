# S2J Package Dashboard - スクリーン仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、スクリーン・アーキテクチャーを定義します。

実装結果、iOS/iPadOS/Android のプラットフォーム UX、Kotlin Multiplatform (KMP) アーキテクチャー、および関連仕様の変更に応じて、更新します。

## 目的

本ドキュメントでは、各スクリーンの責務、表示内容、状態、レイアウト、レスポンシブ挙動およびアクセシビリティ要件を定義します。

目的は、iPhone/iPad/Android において同一のアプリケーションのセマンティクスを維持しながら、各プラットフォームおよびウィンドウサイズに適したスクリーンを提供することです。

## 非目的

本仕様では、下記を必須としません。

* iOS/Android で完全に同一のスクリーン・レイアウト
* スクリーン UI の Kotlin Multiplatform (KMP) 化
* Compose Multiplatform (CMP) によるスクリーン共有
* スクリーンからの API 直接アクセス
* スクリーンからのストレージ直接アクセス
* スクリーンからのクレデンシャル (資格情報) 直接アクセス
* 全スクリーンの3ペイン化
* ディープリンクを、初期バージョンの最優先とすること。実装時期は [`use_cases.md` 優先順位-2](./use_cases.md#優先順位-2) の UC-27を正本とします

## 責務

画面の責務・構成・画面固有の表示を正本とします。

## 非責務

ロード/エラー/空/アクセシビリティ等の横断ルールは [`ui.md`](./ui.md)、Viewport は [`ui-viewport.md`](./ui-viewport.md)、ナビゲーションは [`navigation_spec.md`](./navigation_spec.md)、操作経路は [`ux_flows_spec.md`](./ux_flows_spec.md)、目的は [`use_cases.md`](./use_cases.md)、指標の意味は [`statistics_spec.md`](./statistics_spec.md)、認証状態は [`authentication_spec.md`](./authentication_spec.md)、プライバシー方針は [`security_spec.md`](./security_spec.md)、状態の分類・復元は [`application_state.md`](./application_state.md)、層とネイティブ UI は [`architecture.md`](./architecture.md)、Kotlin Multiplatform (KMP) の HOW は [`kmp_spec.md`](./kmp_spec.md)、コンポーネント境界は [`component_spec.md`](./component_spec.md)、ビジュアル Token は [`design_spec.md`](./design_spec.md)、検証の種類は [`testing_spec.md`](./testing_spec.md)、ファイル名簿は [`specs.md`](./specs.md) を正本とします。

## スクリーンの定義

スクリーンとは、「ナビゲーション上の、一つの独立したアプリケーション・コンテキスト」と定義します。スクリーンは、必ずしも1つの UI ビューと1対1で対応するとは限りません。

## スクリーン/ビュー/コンポーネント

スクリーンはプラットフォーム・ビューを持ち、ビューは UI コンポーネントを合成します。たとえば、パッケージ詳細スクリーンは PackageDetailView を持ち、Header、RepositoryInfo、MetricSummary、StatisticsChart、SecurityAdvisory、PackageActions に分解します。コンポーネント境界は [`component_spec.md`](./component_spec.md) を正本とします。
本仕様は、「スクリーンが何を示すか」だけを定めます。

## スクリーンの責務

スクリーンは、下記を定義します。

* ユーザー・コンテキスト
* 画面状態
* レイアウト
* ナビゲーション・コンテキスト
* コンポーネント・コンポジション

## スクリーンの非責務

スクリーン自身は、下記を直接実装しません。

* Packagist API 通信
* GitHub API 通信
* クレデンシャル (資格情報) ストレージ
* キャッシュ・ストレージ
* スナップショット・ストレージ
* ドメイン・ルール

## スクリーン・アーキテクチャー

層の依存方向は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「スクリーンが ViewModel/プレゼンテーション経由でユースケースを呼び、プロバイダに直接依存しない」ことのみを定めます。

## 初期スクリーン

起動時のルート遷移先は [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「そのスクリーンがダッシュボードの表示内容を持つ」ことのみを定めます。

## スクリーン一覧

初期バージョンでは、下記のスクリーンを定義します。

* ダッシュボード
* パッケージリスト
* パッケージ詳細
* 統計

設定画面のうち Packagist のクレデンシャル (資格情報) 節と、そこへ進むナビゲーションの実装時期は [`use_cases.md` 優先順位-1](./use_cases.md#優先順位-1) の UC-16を正本とします。設定画面の残りの実装時期は [`use_cases.md` 優先順位-2](./use_cases.md#優先順位-2) の UC-31を正本とします。About は設定画面から開き、表示できることの確認も UC-31を正本とします。表示内容は UC-32を正本とします。初期バージョンの最優先ではありません。

## スクリーンのヒエラルキー

```text

```

## 「ダッシュボード」スクリーン

ダッシュボードは、アプリケーションのプライマリ・スクリーンとします。

## ダッシュボードの目的

ダッシュボードは、ユーザーが管理するパッケージおよびお気に入りのパッケージの状態を、一目で把握するためのスクリーンとします。

## 「ダッシュボード」コンテンツ

ダッシュボードでは、下記を表示可能とします。

* 管理対象のパッケージ
* お気に入りのパッケージ
* 統計の概要
* 最新のアップデート
* スナップショットのステータス

## ダッシュボードの優先順位

ダッシュボードの情報の優先順位は、下記の通りです。

1. 管理対象のパッケージ
2. お気に入りのパッケージ
3. 重要統計
4. 最近の変更
5. 二次的な情報

管理対象は、タップや選択の対象とします。取得の実装時期は [`use_cases.md` 優先順位-1](./use_cases.md#優先順位-1) の UC-02を正本とします。認証の設定は UC-16を正本とします。

パッケージ詳細の提示順は [「パッケージ詳細」コンテンツ](#パッケージ詳細コンテンツ) / [パッケージ見出し](#パッケージ見出し) を正本とします。
ビジュアル上のタイポグラフィ対応は、[`design_spec.md`](./design_spec.md) とします。

## ダッシュボードのレイアウト

コンパクト幅では、ダッシュボードの下に管理対象とお気に入りを縦に並べます。

## ダッシュボードのレギュラー・レイアウト

レギュラー幅では、管理対象、お気に入り、統計概要を並列で表示可能とします。2/3ペインの分割は [`navigation_spec.md`](./navigation_spec.md)、到達性は [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、「画面が、どの情報グループを見せるか」だけを定めます。

## ダッシュボードの「空」状態

管理対象のパッケージが存在しない場合、「空」状態を表示します。

## ダッシュボードのエラー状態

ダッシュボードのデータ取得に失敗した場合、エラー状態を表示します。

既存キャッシュが利用可能な場合は、キャッシュ・データを表示可能とします。

## ダッシュボードのリフレッシュ

ダッシュボードは、「引っ張って更新」等のネイティブ・リフレッシュ・インタラクションを利用可能とします。ジェスチャと既存データの維持は、[`ui.md`](./ui.md) を正本とします。

## ダッシュボードのロード

初回ロード時には、必要に応じて、スケルトン/進捗インジケータを表示します。

## 「パッケージリスト」スクリーン

「パッケージリスト」スクリーンは、複数パッケージを一覧表示します。

## パッケージリストのカテゴリー

パッケージリストには、下記のカテゴリーを持たせます。

* 管理対象
* お気に入り

## 管理対象のパッケージ

管理対象/お気に入りの意味は、[`domain_rules.md`](./domain_rules.md) を正本とします。管理対象の取得の実装時期は [`use_cases.md` 優先順位-1](./use_cases.md#優先順位-1) の UC-02を正本とします。認証の設定は UC-16を正本とします。管理対象は、タップや選択の対象とします。お気に入りの追加は認証を要求しません。実装時期は [`use_cases.md` 優先順位-2](./use_cases.md#優先順位-2) の UC-06を正本とします。初期バージョンの最優先ではありません。
本仕様は、「パッケージリスト上の表示カテゴリー」だけを定めます。

## お気に入りのパッケージ

お気に入りのリスト表示も、意味は [`domain_rules.md`](./domain_rules.md) を正本とします。

## パッケージリストの行

パッケージの行には、必要に応じて、下記を表示します。

* パッケージ名
* 説明
* 現在のバージョン
* ダウンロード数
* お気に入り状態

## パッケージリストの並べ替え

パッケージリストのソート条件は、UI 仕様およびドメイン・ルールに従います。

## パッケージリストのフィルター

パッケージリストは、必要に応じて、フィルターを提供します。

## パッケージリストの検索

パッケージ検索の実装時期は [`use_cases.md` 優先順位-1](./use_cases.md#優先順位-1) の UC-04を正本とします。
本仕様は、「検索を提供できる画面構造にする」ことのみを定めます。

## パッケージリストの「空」

該当パッケージが存在しない場合、「空」として扱います。

## パッケージリストのエラー

取得エラーと空の区別は、[`ui.md`](./ui.md) を正本とします。
本仕様は、「パッケージリストが、その区別を表示する」ことのみを定めます。

## 「パッケージ詳細」スクリーン

パッケージ詳細は、1つのパッケージについて詳細情報を表示します。

## 「パッケージ詳細」コンテンツ

* README
* パッケージ・メタデータ
* 依存関係
* リポジトリ
* 現在のバージョン
* ダウンロード数
* 統計
* セキュリティ告知
* お気に入りの状態
* 管理対象の状態

## README

本文の取得元は [`api-github.md` リポジトリ README](./api-github.md#リポジトリ-readme) を正本とします。
本仕様は、「パッケージ詳細のコンテンツに、README を含める」ことのみを定めます。

## 依存関係

見せ方は [`design_spec.md` 依存関係の設計](./design_spec.md#依存関係の設計) を正本とします。
本仕様は、「パッケージ詳細のコンテンツに、依存関係を含める」ことのみを定めます。

## セキュリティ告知

初期バージョンでは、パッケージ詳細にセキュリティ告知を出します。有無と件数の見せ方は [`api-packagist.md` セキュリティ告知のユースケース](./api-packagist.md#セキュリティ告知のユースケース) を正本とします。
本仕様は、「パッケージ詳細のコンテンツに、セキュリティ告知を含める」ことのみを定めます。

## パッケージ見出し

パッケージ見出しには、下記を表示します。

* パッケージ名
* 説明
* 現在のバージョン

## リポジトリ情報

リポジトリ情報には、下記を表示可能とします。

* GitHub リポジトリ
* オーナー
* リポジトリ名
* デフォルト・ブランチ

## パッケージ・アクション

パッケージ詳細では、必要に応じて、下記を提供します。外部 URL の開き方とリフレッシュの見え方は [`ui.md`](./ui.md) を正本とします。

* お気に入り
* お気に入り解除
* Open Packagist
* Open GitHub
* リフレッシュ

## パッケージ詳細のロード

パッケージ詳細は、ナビゲーション後にデータを遅延ロード可能とします。

## パッケージ詳細のキャッシュ

キャッシュ・データが存在する場合、リモートデータ取得前に表示可能とします。鮮度/Stale の判定は [`cache_spec.md`](./cache_spec.md)、Stale の見え方は [`ui.md`](./ui.md) を正本とします。

## パッケージ詳細のエラー

GitHub を特定できないとき、および Packagist も取得できないときの表示順は [`api-github.md` リポジトリ解決失敗](./api-github.md#リポジトリ解決失敗) を正本とします。空とエラーの区別は [`ui.md`](./ui.md) を正本とします。
本仕様は、「失敗時に、原因を短く示し、取れたデータまたは最後のキャッシュを残す」ことのみを定めます。

データ取得に失敗した場合、下記を提供可能とします。

* エラー
* リトライ

## パッケージ詳細のオフライン

オフライン時でも、キャッシュ・データが利用可能であれば、パッケージ詳細を表示可能とします。

## 「統計」スクリーン

「統計」スクリーンは、パッケージの統計情報を時系列で可視化します。キー指標の意味は [`statistics_spec.md`](./statistics_spec.md) を正本とします。

## 統計の範囲

統計は、選択されたパッケージを対象とします。

## 「統計」コンテンツ

表示する指標の意味と対象は、[`statistics_spec.md`](./statistics_spec.md) を正本とします。
本節は、「概要、チャート、期間など画面上の置き場所」だけを定義します。

## 統計の概要

主要指標は、概要カードとして表示可能とします。

## 統計のチャート

履歴データは、チャート・コンポーネントで可視化します。

チャートは、タッチ/ポインタで操作可能とします。データポイント選択時は、日付、値、出典を表示します。ジェスチャは、タップ / ドラッグ / ピンチ / スクロールを必要な場合に限定します。水平スクロールが必要な場合の到達可能性は [`ui-viewport.md`](./ui-viewport.md) に従います。

## 統計の期間

統計では、必要に応じて、期間を選択可能とします。期間にデータがない場合の扱いは、[`statistics_spec.md`](./statistics_spec.md) を正本とします。

例:

* `7 Days`
* `30 Days`
* `90 Days`
* `1 Year`
* All

## 統計データの可用性

指標ごとに取得可能な期間が異なる場合、その違いを考慮します。

## 統計の欠落データ

欠測を0にしないことは [`domain_rules.md`](./domain_rules.md)、チャート上のギャップは [`statistics_spec.md`](./statistics_spec.md) を正本とします。
本仕様は、「統計画面が欠測期間を隠して連続値に見せない」ことのみを定めます。

## 統計の部分データ

一部指標のみ取得できた場合、取得できた指標を表示可能とします。部分失敗の見え方は、[`ui.md`](./ui.md) を正本とします。

## 統計のスナップショット

長期統計は、スナップショット・データを利用します。

## 統計のリフレッシュ

統計のリフレッシュでは、既存チャートを、可能な限り、維持します。既存データの維持は、[`ui.md`](./ui.md) を正本とします。

## 統計のロード

チャート表示中のロードは、[`ui.md`](./ui.md) を正本とします。
本仕様は、「統計画面が、意味のない空白だけにならない」ことのみを定めます。

## 統計のエラー

リトライ可能なエラー UI は、[`ui.md`](./ui.md) を正本とします。
本仕様は、「統計取得エラーを、画面固有のリトライ状態として出す」ことのみを定めます。
