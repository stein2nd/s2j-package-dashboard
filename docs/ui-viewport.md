# S2J Package Dashboard - Viewport 整合性仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、**UI Viewport 整合性 (表示領域の整合性)** を定義します。

本仕様における Viewport とは、アプリケーションがその時点で UI を表示可能な実効表示の領域を指します。

Viewport は、単純な物理画面サイズではなく、下記を考慮した表示領域として扱います。

* デバイスの画面サイズ
* 画面の向き
* セーフエリア
* ウィンドウサイズ
* iPadOS のスプリット・ビュー/ステージマネージャー等によるウィンドウサイズ
* Android のウィンドウサイズ・クラス
* ダイナミック・タイプ/フォント・スケーリング
* システム UI
* ナビゲーション UI/ツールバー/タブバー等による占有領域
* キーボード等の一時的な表示領域の変化

本仕様の目的は、下記を保証することです。

1. 表示されている UI 要素が、実際に到達可能であること
2. UI 要素が、画面外に意図せず配置されないこと
3. 画面サイズや向きの変更に対して、UI が安定して再配置されること
4. コンテンツが、切り取られたり隠れたりしないこと
5. タッチ・クリック等の操作領域が、適切に確保されること
6. iPhone/iPad/Android の異なる Viewport に対して、適応的に表示できること

Viewport 整合性の正本は、本仕様とします。
横断的な UI 挙動は [`ui.md`](./ui.md)、画面構成は [`screen_spec.md`](./screen_spec.md)、ナビゲーションは [`navigation_spec.md`](./navigation_spec.md) を参照します。

## 目的

本仕様は UI Viewport 整合性 (表示領域の整合性) を保証します。表示中の UI が到達可能であり、向きやウィンドウサイズの変更に対して、安定して再配置され、コンテンツが意図せず隠れないことを、正本として定義します。

## 非目的

本仕様は、ナビゲーション・グラフ、スクリーンの責務、ドメイン・モデル、API 契約、色/タイポグラフィのデザイントークン、アニメーションの詳細を直接定義しません。

## 責務

到達可能性、レイアウト安定性、コンテンツ整合、操作整合、v1のリリースブロック、Viewport テスト行列を定義します。

## 非責務

横断 UI は [`ui.md`](./ui.md)、画面構成は [`screen_spec.md`](./screen_spec.md)、ナビゲーションは [`navigation_spec.md`](./navigation_spec.md)、ビジュアル Token は [`design_spec.md`](./design_spec.md)、向き変更後に何を保持するかは [`application_state.md`](./application_state.md) を正本とします。

## 基本原則

### Viewport を固定サイズとして扱わない

UI は、特定のデバイスの物理画面サイズを前提として設計してはなりません。下記のような固定値への依存を避けます。UI は、その時点で利用可能なウィンドウ/Viewport に応じて、レイアウトを決定します。

* 特定デバイスの横幅
* 特定デバイスの縦幅
* 特定のアスペクト比
* 「この端末なら必ず表示できる」という前提
* 固定された画面座標

## Viewport 整合性

本アプリケーションでは、下記を **Viewport 整合性** の基本要件とします。

### 到達可能性

「見えていること」と「操作できること」は、同一の品質条件として扱います。

画面上に表示されている操作可能な UI 要素は、ユーザーが実際に操作可能でなければなりません。特に下記を禁止します。

* 画面端に隠れて、タップできないボタン
* セーフエリアの外側に配置された、操作要素
* 親ビューのクリッピングにより、操作できない要素
* 水平方向に意図せずはみ出した UI
* 見えているが、実際のヒットエリアが画面外にある UI
* ScrollView の外側に存在するが、スクロールによって到達できない UI

### レイアウトの安定性

レイアウトの変更が必要な場合は、可能な限り、一貫したレイアウト計算結果を直接表示します。

Viewport の変化によってレイアウトを再計算する場合でも、不必要なビジュアル的ジャンプを発生させてはなりません。特に下記を禁止します。

* 起動直後に左寄せされた後、遅れて中央寄せになる
* 画面回転時に、コンテンツが一時的に画面外に移動する
* データ取得完了とは無関係に、UI の位置が大きく移動する
* ナビゲーション UI の表示・非表示によって、コンテンツが不必要に跳ねる
* ウィンドウサイズ・クラスの変更時に、一時的な不正レイアウトを表示する

### コンテンツの整合性

ユーザーに提示する情報は、Viewport の制約によって、意図せず欠落してはなりません。下記を禁止します。

* テキストの、意図しないクリッピング
* パッケージ名の途中切断
* 数値の途中切断
* チャートの軸・凡例のクリッピング
* ボタンのラベルが表示されない状態
* エラー・メッセージの一部だけが表示される状態
* アクセシビリティに必要な情報が、画面外に消える状態

表示領域が不足する場合は、下記のいずれかを使用します。ただし、水平スクロールは、情報構造上、必要な場合に限定して、使用します。

* 改行
* 省略 + 詳細表示
* 垂直スクロール
* 水平スクロール
* アダプティブ・レイアウト
* 複数ペイン・レイアウト
* 別画面への遷移

### インタラクションの整合性

UI の操作領域は、表示領域および UI 階層との整合性を保たなければなりません。下記を禁止します。

* 親ビューのジェスチャが、子ビューの操作を妨げる
* スクロール・ジェスチャとボタン・ジェスチャの競合によって、操作不能になる
* 見た目とヒットエリアが、大きく異なる
* UI 要素同士の重なりによって、操作対象を誤認する
* オーバーレイが、意図せず下層 UI の操作を遮断する

## セーフエリア

### 基本方針

プラットフォームが提供するセーフエリアを尊重します。

Apple の UI ガイドラインでも、セーフエリアは、システム UI やデバイス固有の表示・操作領域によって覆われない領域として扱われています。

(参考: [Layout | Apple Developer Documentation](https://developer.apple.com/design/human-interface-guidelines/layout?changes=la__1_8_1))

したがって、アプリケーション独自に「画面端から何 pt 空ければ安全」といった、固定ルールを設定してはなりません。

### 操作 UI

下記の UI は、セーフエリア内に配置します。特に画面端に配置される操作 UI は、セーフエリアと実際のヒットエリアの両方を確認します。

* ボタン
* ナビゲーション・アイテム
* ツールバー アイテム
* タブ アイテム
* トグル
* メニュー
* TextField
* SearchField
* スライダー
* チャート操作 UI

## アダプティブ・レイアウト

UI は「端末種類」ではなく、利用可能な Viewport/ウィンドウサイズを基準として適応します。コンパクト/ミディアム/展開を優先し、`if iPhone` / `if iPad` を基本設計にしません。

画面上の置き場所は [`screen_spec.md`](./screen_spec.md)、スプリット・ビュー/縦積みの折りたたみは [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「狭い Viewport では縦スクロールで到達可能にし、画面座標に依存したレイアウトを最小にする」ことのみを定めます。

## iOS/iPadOS

SwiftUI のアダプティブ機構を使います。`NavigationStack` / `NavigationSplitView` は [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「`GeometryReader` による、画面座標の依存を最小にする」ことのみを定めます。

## Android

物理デバイスではなく、ウィンドウサイズ・クラスを基準とします。`ListDetailPaneScaffold` 等のペイン構成は [`navigation_spec.md`](./navigation_spec.md) を正本とします。

## 画面の向き変更

縦置き/横置きの切り替えによって、UI が破綻してはなりません。対象デバイスは [基準端末](#基準端末) を正本とします。

画面の向き変更時には、新しい Viewport に対してレイアウトを再計算します。中間レイアウトを見せません。保持するアプリケーション状態は [`application_state.md`](./application_state.md) を正本とします。

同一コンテンツを表示可能な場合、スクロール位置を、可能な限り、維持します。レイアウト・モードが変わる場合は、オフセットではなく、現在表示していたコンテンツを基準に復元します。

## ダイナミック・タイプ / フォント・スケーリング

UI は、ダイナミック・タイプ/フォント・スケーリングに対応します。

Apple では、ダイナミック・タイプを含む文字サイズ変更への適応が UI の適応性の一部として扱われています。

(参考: [Layout | Apple Developer Documentation](https://developer.apple.com/design/human-interface-guidelines/layout?changes=la__1_8_1))

Android でも、フォント・スケーリングを含むシステム設定 (Configuration) 変更に対して、UI の連続性の維持が求められます。

(参考: [Get started with adaptive apps | Adaptive Apps | Android Developers](https://developer.android.com/develop/adaptive-apps/guides/get-started-with-adaptive-apps?hl=en))

### 要件

下記を禁止する。

* 固定高さのテキスト・コンテナ
* 固定行数を前提とした、重要情報
* 大きな文字サイズでのクリッピング
* ボタン・ラベルのクリッピング
* 数値・単位の重なり
* チャート・ラベルのクリッピング

## 長いコンテンツ

S2J Package Dashboard では、外部 API から取得する文字列長を保証できません。したがって、長い文字列を通常ケースとして扱います。

対象:

* パッケージ名
* 説明
* リポジトリ名
* メンテナー名
* バージョン
* リリースノート
* エラー・メッセージ

### パッケージ名

原則として、パッケージ名は、省略せず表示可能な構成を優先します。

表示領域が不足する場合は、下記のいずれかを使用します。

1. 改行
2. 省略
3. 詳細ビュー
4. ツールチップ/アクセシビリティ・ラベル

## 巨大な数値

S2J Package Dashboard では、下記のような大きな数値を扱います。

* ダウンロード数
* GitHub スター数
* フォーク数
* Issue 数
* PR 数
* 貢献者数

下記を保証します。

* 数値が画面外にはみ出さない
* 桁数増加によって、カードのレイアウトが破綻しない
* 単位表示と数値が重ならない
* ロケールに応じた、数値の書式設定を使用する

例:

* 1,234
* 12.4K
* 1.2M
* 1.2B

ただし、略記によって意味があいまいになる場合は、完全な値を確認できる UI を提供します。

## チャート

統計チャートは、Viewport に応じて、適応します。コンパクト/展開とも、チャートは横幅に応じて、表示密度を調整します。下記を禁止します。

* X 軸ラベルのクリッピング
* Y 軸ラベルのクリッピング
* 凡例の画面外配置
* チャート操作領域の画面外配置
* 数値ツールチップが、画面外に完全に消える状態

## 水平方向のオーバーフロー

原則として、アプリケーション全体に、意図しない水平方向のオーバーフローを発生させません。特に下記を禁止します。

```text
┌─────────────────────┐
│ コンテンツ ────────────┼──→
└─────────────────────┘
```

画面全体が、横方向にスクロール可能になってしまう場合は、レイアウトの不具合とみなします。

ただし、下記のように、情報構造上、水平スクロールが必要な場合は、例外とします。この場合でも、水平スクロールの存在を、ユーザーが認識できることを確認します。

* 横方向チャート
* 横方向テーブル
* 明示的な、水平コレクション
* 横方向カルーセル

## Viewport オーバーフローの検出

開発時および UI テストにおいて、下記を検査対象とします。

### クリッピング

* テキストのクリッピング
* ボタンのクリッピング
* カードのクリッピング
* チャートのクリッピング
* ナビゲーション・アイテムのクリッピング

### オーバーフロー

* 水平方向のオーバーフロー
* 垂直方向のオーバーフロー
* セーフエリアのオーバーフロー
* ヒットエリアのオーバーフロー

### オーバーラップ

* ボタン / ボタン
* テキスト / アイコン
* カード / カード
* チャート / 凡例
* ナビゲーション / コンテンツ
* オーバーレイ / インタラクティブ要素

## 状態変更による Viewport 安定性

ロード/リフレッシュ/エラー/空 の状態分類は [`application_state.md`](./application_state.md)、見え方は [`ui.md`](./ui.md) を正本とします。
本仕様は、「状態切替で、主要コンテンツが不必要に移動しない」ことのみを定めます。

## ナビゲーション UI と Viewport

ナビゲーション UI は、コンテンツ・エリアと競合してはなりません。

ナビゲーション UI の表示状態が変化した場合でも、下記を保証する。

* コンテンツがクリッピングされない
* 操作対象が隠れない
* スクロール位置が不必要に失われない
* レイアウトが不必要にジャンプしない

ナビゲーションの意味論については [`navigation_spec.md`](./navigation_spec.md) を信頼できる情報源 (SoT) とします。

## アクセシビリティ

Viewport 整合性は、アクセシビリティを含みます。

UI は、文字サイズやアクセシビリティ設定を変更しても、主要な情報および操作を利用可能な状態に維持します。

対象:

* ダイナミック・タイプ
* フォント・スケーリング
* VoiceOver
* TalkBack
* ラージ・テキスト
* 太字テキスト
* 視差効果を減らす
* 高コントラスト
* タッチ・ターゲット

### iPhone

* `iPhone 16 Pro Max`
* `iOS 26.6`

### iPad

* `iPad Air 5th generation`
* `iPadOS 26.6`

### Android

* 会社支給 Android デバイス

## Viewport 受け入れ条件

下記をすべて満たした場合、Viewport 整合性を満たすものとします。

### A. 到達可能性

* [ ] すべての、表示中の操作 UI を操作できる
* [ ] セーフエリア外に、重要な操作 UI が存在しない
* [ ] ヒットエリアが、画面外に存在しない

### B. レイアウトの安定性

* [ ] 起動時に、不自然なレイアウト・ジャンプが発生しない
* [ ] 画面の向き変更時に、不自然なレイアウト・ジャンプが発生しない
* [ ] ウィンドウ・リサイズ時に、不自然なレイアウト・ジャンプが発生しない
* [ ] 読込中/読込完了の状態変更による、不必要なレイアウトズレが発生しない

### C. コンテンツの整合性

* [ ] 重要なテキストが、クリッピングされない
* [ ] 数値が、クリッピングされない
* [ ] チャートが、クリッピングされない
* [ ] エラー/空の状態が、クリッピングされない

### D. インタラクションの整合性

* [ ] ジェスチャ・コンフリクトがない
* [ ] オーバーレイによる、意図しない操作不能がない
* [ ] スクロールとインタラクティブ要素の競合がない

### E. 適応性

* [ ] 縦置き/横置きの双方で、利用可能
* [ ] iPad の異なるウィンドウサイズに適応する
* [ ] Android のウィンドウサイズ・クラスに適応する
* [ ] ダイナミック・タイプ/フォント・スケーリングに適応する

### F. アクセシビリティ

* [ ] 大きなテキストで、UI が破綻しない
* [ ] VoiceOver/TalkBack で、主要操作が可能
* [ ] タッチ・ターゲットが、適切に確保されている

## v1のリリースブロック

v1では下記をリリースブロックとします。

* 重要 UI が、Viewport 外にある
* 重要 UI が、タップできない
* テキストが、クリップされる
* チャートが、操作不能
* 向き変更で、レイアウトが破綻する
* iPad リサイズで、レイアウトが破綻する

向き変更 (縦置き↔横置き) で、下記が発生することもリリースブロックとします。

* 予期せぬ、左寄せ
* 予期せぬ、中央寄せ
* 切り取られたコンテンツ
* ロストの状態
* 到達不能な、コンテンツ

## 実装原則

UI の共通化を目的として、iOS/Android の UI 実装自体を無理に共通化しません。

共通化対象は、下記を優先します。

* スクリーンのセマンティクス
* ナビゲーションのセマンティクス
* 状態
* ドメイン・ロジック
* アプリケーション・ロジック

実装時には、下記を原則とします。

### iOS/iPadOS

SwiftUI で、アダプティブ・レイアウトを組み、セーフエリア/サイズ/アクセシビリティに合わせます。

### Android

Android は、今後のターゲットです。初期バージョンの UI は、SwiftUI のみです。Android 版の開発に着手したタイミングで、Jetpack Compose でウィンドウサイズ・クラスに合わせ、アダプティブ・レイアウトとアクセシビリティ/フォント・スケーリングを扱います。時期は [`overview.md`](./overview.md) を正本とします。
