# S2J Package Dashboard - アプリケーション状態の仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、アプリケーション状態のライフサイクル、保持範囲、保存・復元方針を定義します。

復元対象と復元順位の正本は本仕様とします。状態遷移は [`state_machine.md`](./state_machine.md) を正本とします。

## 目的

本仕様は、S2J Package Dashboard におけるアプリケーション状態の定義、ライフサイクル、保持範囲、保存・復元方針を定めます。

復元対象、復元順位、保持しないものの正本は本仕様とします。復元の状態遷移は [`state_machine.md`](./state_machine.md) を正本とします。

目的は、「ユーザーがアプリケーションを離れる前に行っていた操作を、可能な限り、自然に再開できること」とします。

## 非目的

本仕様では、下記を要求しません。特に、「アプリケーションを再起動したら、完全に同じ内部状態に戻す」ことを目的としません。

* すべての UI の状態の、完全な復元
* スクロール位置の、完全な復元
* API レスポンスの、状態復元
* ネットワーク・リクエストの、再開
* 非同期タスクの、復元
* クレデンシャル (資格情報) の、状態復元
* キャッシュの、完全な復元
* アプリケーション状態の、クラウド同期
* iOS / Android 間のアプリケーション状態同期

## 責務

実行中および再起動時に必要な状態の分類・保持・復元対象を定義します。対象はライフサイクル、ナビゲーション、選択、検索/フィルター、統計表示、ロード、リフレッシュ、エラー、オフライン/Stale、認証、ウィンドウ/プレゼンテーション、復元データとします。

## 非責務

状態遷移は [`state_machine.md`](./state_machine.md) を正本とします。
状態の見え方 (ロード/エラー/空) は [`ui.md`](./ui.md) を正本とします。
新鮮/Stale の判定は [`cache_spec.md`](./cache_spec.md)、認証状態は [`authentication_spec.md`](./authentication_spec.md) を正本とします。
永続データの保存 HOW は [`storage_spec.md`](./storage_spec.md) / [`ios_spec.md`](./ios_spec.md) / [`android_spec.md`](./android_spec.md) を正本とします。
Kotlin Multiplatform (KMP) のソースセット/移行手順は [`kmp_spec.md`](./kmp_spec.md)、向き変更時のレイアウトは [`ui-viewport.md`](./ui-viewport.md)、ルート遷移先は [`navigation_spec.md`](./navigation_spec.md)、検証の種類は [`testing_spec.md`](./testing_spec.md)、ファイル名簿は [`specs.md`](./specs.md) を正本とします。
パッケージのドメイン・モデル、API レスポンス、永続化パッケージ・データ、統計スナップショット、クレデンシャル (資格情報) Secret、キャッシュ・データは各専門仕様を正本とします。

## 状態の分類

下記は、保存期間と責務にもとづき、アプリケーション状態を分類したものです。アプリケーション状態と永続化データを、混同してはなりません。特に、UI の状態を復元するためだけに、パッケージ本体や統計スナップショットを、アプリケーション状態として保存してはなりません。

| カテゴリー | 説明 | 例 |
| --- | --- | --- |
| 永続化データ | ユーザーまたはアプリケーションが、永続的に保持するデータ | パッケージ、お気に入り、スナップショット |
| 復元可能なアプリケーション状態 | 再開時に復元することで、UX を維持する状態 | ナビゲーション・パス、選択中のパッケージ |
| セッション状態 | 現在のアプリケーション・セッション中のみ必要な状態 | ロード、更新中 |
| UI ローカル状態 | 特定のビュー / コンポーネント内だけで必要な状態 | 展開状態、フォーカス |
| 派生の状態 | 他の状態から算出可能な状態 | `isRefreshing` |
| 単発イベント | 一度だけ処理されるイベント | リトライ、URL の Open |

## アプリケーション状態モデル

アプリケーション状態は、概念的に、下記の構造を持ちます。これは、実装上の単一 `ApplicationState` struct/class を必須とするものではありません。各プラットフォームの実装では、適切な状態 Holder/ViewModel/Scene の状態等に分割してかまいません。ただし、**状態の意味論は、プラットフォーム間で一致させます**。

* ライフサイクル: `launching` / `active` / `inactive` / `background`
* ナビゲーション: `root` / `path` / `presentedDestination`
* 選択: `selectedPackage` / `selectedStatistic`
* クエリー: `searchQuery` / `filters`
* 統計: `period` / `source`
* データ: `loadState` / `refreshState` / `staleState`
* 認証: `packagist` / `github`
* 復元: `version` / `restorationStatus`

## アプリケーションのライフサイクルの状態

アプリケーションのライフサイクルの状態は、アプリケーションが現在、どの状態にあるかを表します。値は、起動中/アクティブ/非アクティブ/バックグラウンドとします。

遷移は [`state_machine.md`](./state_machine.md) を正本とします。
本仕様は「分類」だけを定めます。

### 起動中

アプリケーションが起動し、初期状態を構築している状態です。

この状態では、下記を行います。

1. 永続化データの読込
2. 復元可能なアプリケーション状態の読込
3. 認証の状態の確認
4. キャッシュの状態の確認
5. 初期ナビゲーション状態の構築
6. 必要なデータ・フェッチの開始

### アクティブ

ユーザーがアプリケーションを操作可能な状態です。

通常のアプリケーション状態遷移は、この状態で発生します。

### 非アクティブ

アプリケーションが、一時的に操作対象ではない状態です。この状態になっただけで、アプリケーション状態を破棄してはなりません。

例:

* システム UI 表示
* Scene 遷移
* 一時的な割り込み

### バックグラウンド

アプリケーションが、バックグラウンドに移行した状態です。

バックグラウンド移行時には、必要な復元可能なアプリケーション状態を、保存可能な状態にしておきます。

ただし、OS によるバックグラウンド実行や保存タイミングを保証してはなりません。

## ナビゲーション状態

ナビゲーション状態は、ユーザーが現在どのアプリケーション・コンテキストにいるかを表します。

到達可能な経路は [`navigation_spec.md`](./navigation_spec.md) / [`ux_flows_spec.md`](./ux_flows_spec.md) を正本とします。
本仕様は、「ナビゲーション状態が、識別子を保持する」ことのみを定めます。

ナビゲーション状態には、少なくとも、下記を含みます。

* 現在ルート
* ナビゲーション・パス
* 選択された遷移先
* モーダル表示 / シート
* ディープリンク遷移先

ナビゲーション状態は、ドメイン・データ自体ではなく、**ドメイン・データを参照するための識別子** を保持します。たとえば、パッケージ詳細を復元する場合、下記とします。

* Good:
    * PackageIdentifier = "vendor/package"
* Bad:
    * PackageDetailViewModel 全体
    * パッケージ API レスポンス全体

Apple の SwiftUI でも `NavigationStack` のパスは、アプリケーションが管理可能な状態として扱え、ナビゲーション・パスの復元がサポートされています。

(参考: [Understanding the navigation stack | Apple Developer Documentation](https://developer.apple.com/documentation/swiftui/understanding-the-navigation-stack))

## 選択の状態

選択の状態は、現在ユーザーが選択している対象を表します。選択対象は、可能な限り、識別子で保持します。

例:

`selectedPackage = vendor/package`

### パッケージの選択

パッケージ詳細を表示している場合、`selectedPackageID` を保持します。パッケージの詳細データ自体は、リポジトリから取得します。

### 無効な選択

復元対象パッケージが存在しない場合、`selectedPackageID` を破棄し、親遷移先にフォールバックします。存在しないパッケージを復元するために、古い API レスポンスをアプリケーション状態に保持してはなりません。

## 検索とフィルターの状態

検索画面で入力された状態を保持します。検索の結果自体は、アプリケーション状態として保存しません。検索条件のみを復元し、必要に応じて、リポジトリ/キャッシュから結果を再構築します。

対象:

* 検索クエリー
* フィルター
* ソート順序
* 選択された範囲

例:

```text
searchQuery = "wordpress"
filter = "all"
sortOrder = "name"
```

## 統計表示の状態

「統計」スクリーンの表示条件を保持します。

対象:

* 統計期間
* 統計の出典
* 選択された指標
* 選択中のパッケージ

例:

`statisticsPeriod = monthly`
`statisticsSource = packagist`

一方、統計の実データは、永続化データ/キャッシュ/スナップショットの責務とします。

アプリケーション状態が持つのは、期間/出典等の表示条件であり、スナップショット本体は [`storage_spec.md`](./storage_spec.md) を正本とします。

## データ・ロードの状態

データ・ロードの状態は、現在のデータ取得処理の状態を表します。値は、アイドル/読込中/読込完了/空/エラーとします。

遷移は [`state_machine.md`](./state_machine.md) を正本とします。
本仕様は「分類」だけを定めます。

### 読込中

初回データの「取得中」を示します。

### 読込完了

要求したデータが「取得済み」を示します。

### 空

要求は成功したが、表示対象データが「存在しない」を示します。

### エラー

データ取得に「失敗した」を示します。

エラー状態には、必要に応じて、正規化された `ApplicationError` を保持します。

## リフレッシュの状態

リフレッシュは、ロードと区別します。

遷移の形式は [`state_machine.md`](./state_machine.md)、既存データの見え方は [`ui.md`](./ui.md) を正本とします。
本仕様は、「更新中をセッション状態として持ち、失敗しても既存データを破棄しない」ことのみを定めます。

## Stale の状態

新鮮/Stale/利用不能の判定は [`cache_spec.md`](./cache_spec.md) を正本とします。
本仕様は、「表示中データが Stale であることを、アプリケーション状態として持つことが可能である」「Stale を、エラーと混同しない」ことのみを定めます。

## オフラインの状態

オフライン時の既存表示は [`ui.md`](./ui.md)、キャッシュ利用は [`cache_spec.md`](./cache_spec.md) を正本とします。
本仕様は、「オフラインを、アプリケーション状態として持つことが可能である」「エラーと同一視しない」ことのみを定めます。

## 認証の状態

UI に出してよい状態は [`authentication_spec.md`](./authentication_spec.md) を正本とします。
保存 HOW は [`ios_spec.md`](./ios_spec.md) / [`android_spec.md`](./android_spec.md) を正本とします。
本仕様は、「クレデンシャル (資格情報) の値ではなく `isAuthenticated` / `accountIdentifier` / `credentialStatus` 等の非秘密情報を、アプリケーション状態として持つ」ことのみを定めます。

## 状態復元

状態復元は、アプリケーションが中断された後に、ユーザーが以前の操作地点に戻れることを目的とします。何を復元するかは本節、どう遷移するかは [`state_machine.md` 状態復元の遷移](./state_machine.md#状態復元の遷移) を正本とします。
SceneStorage / SavedStateHandle の実装は [`ios_spec.md`](./ios_spec.md) / [`android_spec.md`](./android_spec.md) を正本とします。
本仕様は、「復元可能な状態を、識別子/クエリー/選択/ナビゲーション等の軽量情報に限り、大規模データは永続化ストレージ/キャッシュから再構築する」ことのみを定めます。

## 状態復元の復元順位

復元対象には、復元順位を設けます。これは、ユースケースの実装時期である優先順位とは別です。

### 復元順位-1: 必ず復元

* 現在パッケージ
* ナビゲーション・コンテキスト
* 検索クエリー
* 統計期間
* 選択されたフィルター
* 進行中のユーザー入力で、明示的に必須とされているもの

### 復元順位-2: 復元すべき

* 選択された指標
* ソート順序
* 選択されたタブ
* プレゼンテーション関連の選択

### 復元順位-3: 復元してもよい

* スクロール位置
* 展開/折りたたみ UI の状態
* 一時プレゼンテーションのユーザー設定 (Preference)

### 復元しない

* ロードの状態
* 更新中の状態
* ネットワーク・エラー・オブジェクト
* リクエスト・オブジェクト
* タスク/コルーチン/非同期処理
* クレデンシャル (資格情報) Secret
* API レスポンス・オブジェクト
* キャッシュ・コンテンツ
* 統計スナップショット自体

## 復元とデータ・リロード

アプリケーション状態の復元と、データの復元を分離します。識別子を復元したあと、`Repository.find` で ローカルデータを引き、必要ならリモート・フェッチします。
キャッシュ利用は [`cache_spec.md`](./cache_spec.md) を正本とします。

アプリケーション状態が復元されたことを理由に、古い API レスポンスをそのまま再利用してはなりません。

ローカル・キャッシュが利用可能な場合は、キャッシュの方針 に従って利用する。

## 状態のバージョン管理

復元可能なアプリケーション状態には、バージョンを持たせます。

例:

`stateVersion = 1`

アプリケーション更新によって状態スキーマが変更された場合、格納済み状態のバージョンを判定します。互換なら復元、移行可能なら移行して復元、非互換なら破棄して デフォルトの状態にします。

古い状態を無理に復元して不整合を発生させるよりも、復元可能性を判定し、安全に初期状態にフォールバックすることを優先します。

## 無効な復元

復元された状態が、現在のデータと整合しない場合は、安全なフォールバックを行います。

復元したパッケージ ID が存在しなければ、パッケージ詳細を外し、パッケージリストに戻ります。復元したナビゲーション・パスに未知の遷移先があれば、無効パスを捨て、最も近い有効な親を復元します。

アプリケーション起動を失敗させる原因となる状態復元は、許可しません。

## 画面の向きの変更と、ウィンドウサイズの変更

レイアウトの再計算と中間レイアウト禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、「向き変更/ウィンドウサイズ変更で、選択中のパッケージ/ナビゲーション・コンテキスト/検索クエリー/統計期間/フィルターを破棄しない」ことのみを定めます。

## iPad の複数ウィンドウ

複数 Scene のレイアウトは [`ui-viewport.md`](./ui-viewport.md)、ナビゲーションは [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「ナビゲーション状態/選択状態を Scene 単位で持ち、永続化データと混同しない」ことのみを定めます。

## Android システム設定 (Configuration) の変更

向き変更/リサイズのレイアウトは [`ui-viewport.md`](./ui-viewport.md)、SavedStateHandle は [`android_spec.md`](./android_spec.md) を正本とします。
本仕様は、「システム設定変更後も、スクリーンの状態を維持し、大規模データは、ローカル永続化から再構築する」ことのみを定めます。

## Kotlin Multiplatform (KMP) 境界

共有対象の優先順位は [`architecture.md`](./architecture.md)、ソースセット/モジュール配置は [`kmp_spec.md`](./kmp_spec.md) を正本とします。
本仕様は、「アプリケーション状態の意味論 (選択/クエリー/期間/ロード等) がプラットフォームに依存しない」ことのみを定めます。

## 状態の遷移

遷移の形式は [`state_machine.md`](./state_machine.md) を正本とします。
本仕様は、「アプリケーション状態が、イベントで変わり、I/O を状態自体に混ぜない」ことのみを定めます。

## 派生の状態

原則として、他の状態から算出可能な値は、保存しません。

たとえば、`isRefreshing` が `refreshState == 更新中` から算出できる場合、独立した永続化状態として保存しません。

レデューサー が Stored 状態にしないことは [`state_machine.md`](./state_machine.md) を正本とします。

## 単発イベント

一度きりの操作は、イベントであり、復元可能なアプリケーション状態に含めません。

イベント/エフェクトの形式は [`state_machine.md`](./state_machine.md) を正本とします。
本仕様は、「リトライ/URL の Open/確認/Navigate 等を永続化しない」ことのみを定めます。

## 永続化の境界

保存先の実装は、永続データ [`storage_spec.md`](./storage_spec.md) / [`ios_spec.md`](./ios_spec.md) / [`android_spec.md`](./android_spec.md)、キャッシュ [`cache_spec.md`](./cache_spec.md)、アプリケーション状態に クレデンシャル (資格情報) [`authentication_spec.md`](./authentication_spec.md) を正本とします。
本仕様は、「復元可能なアプリケーション状態と永続化データを、同一ストアに混ぜない」ことのみを定めます。

## セキュリティ

復元可能なアプリケーション状態にクレデンシャル (資格情報) を入れないことは [`authentication_spec.md`](./authentication_spec.md) / [`security_spec.md`](./security_spec.md) を正本とします。
本仕様は、「復元スナップショット/ログ/アナリティクス/クラッシュ・レポートに、Secret を含めない」ことのみを定めます。

## 状態復元の失敗

状態復元に失敗した場合、アプリケーションは、可能な限り、通常起動にフォールバックします。失敗時の遷移は [`state_machine.md`](./state_machine.md) を正本とします。

状態復元の失敗は、それ自体を致命的なアプリケーション・エラーとして扱いません。

## デフォルトの状態

復元データがないときのルート遷移先は [`navigation_spec.md`](./navigation_spec.md)、初期スクリーンの表示内容は [`screen_spec.md`](./screen_spec.md) を正本とします。
本仕様は、「選択/検索/フィルターを空、ロード/リフレッシュをアイドル、認証は現在状態を読み、データはローカルから読む」ことのみを定めます。
統計期間の初期値は [`statistics_spec.md`](./statistics_spec.md) を正本とします。

## その他の仕様との関係

ファイル名簿は [`specs.md`](./specs.md)、統合の見取り図は [`spec.md`](./spec.md) を正本とします。
本仕様の分担は [非責務](#非責務) を正本とします。

## 受け入れ条件

検証の種類は [`testing_spec.md`](./testing_spec.md) を正本とします。
本仕様の合格条件は、状態の分類、[復元順位](#復元順位)、[状態復元の失敗](#状態復元の失敗) が実装されていることとします。向き変更/ウィンドウ変更した後のレイアウトは [`ui-viewport.md`](./ui-viewport.md)、クレデンシャル (資格情報) を復元に入れないことは [`authentication_spec.md`](./authentication_spec.md) / [`security_spec.md`](./security_spec.md) を正本とします。
Kotlin Multiplatform (KMP) の判定は、復元セマンティクスが、プラットフォーム復元 API に依存しないことだけとします。
