# S2J Package Dashboard - UI/UX 仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、UI/UX の挙動を定義します。

iOS/iPadOS/Android 実装、ユーザビリティ・テスト、アクセシビリティ・テスト、Kotlin Multiplatform (KMP) 移行等に応じて、更新します。

## 目的

本ドキュメントでは、S2J Package Dashboard の横断的な UI/UX 挙動を定義します。対象は、ロード/エラー/空/オフライン/Stale、共通インタラクション、アクセシビリティ、ローカライズ、視差効果を減らす、フォーカス、プラットフォーム・ネイティブ UI の原則です。

## 非目的

本仕様は、画面構成、ナビゲーションのヒエラルキー、Viewport 整合性の正本になることを目的としません。

## 責務

全画面に共通する UI の状態表示、破壊的なアクション、アクセシビリティ/ローカライズ/視差効果を減らす、の横断ルールを正本とします。

## UI/UX 基本方針

下記を基本原則とします。

1. 「情報」ファースト
2. 操作可能性を最優先する
3. アクセシビリティを後付けにしない
4. ロード/エラー/空/オフラインを正式な UI 状態として扱う
5. プラットフォーム・ネイティブ UX を尊重する

Viewport / サイズ・クラス / 向きの要件は [`ui-viewport.md`](./ui-viewport.md) を正本とします。

## プラットフォーム UI

ネイティブ UI は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「ビジネス・ロジック/ドメイン・ロジックを UI 層から分離する」ことのみを定めます。

## UI 層境界

層の置き場所は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「SwiftUI が Packagist/GitHub API を直接呼び出さず、ビュー→プレゼンテーション→ユースケース→ドメインとする」ことのみを定めます。初期バージョンの UI は SwiftUI のみです。Android 版の開発に着手したあとの Jetpack Compose も、同じ向きにします。時期は [`overview.md`](./overview.md) を正本とします。

## プラットフォームの独立性

ネイティブ UI API をドメイン仕様に持ち込まないことは [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「SwiftUI のコンポーネント API をドメインに漏らさない」ことのみを定めます。Android 版の開発に着手したあとの Jetpack Compose も、同様にドメインへ漏らしません。時期は [`overview.md`](./overview.md) を正本とします。

## 画面、ナビゲーション、Viewport

画面/ナビゲーション/ Viewport /操作経路の正本は [非責務](#非責務) を正本とします。

## Undo

削除等の可逆的アクションでは、必要に応じて、Undo を提供します。

## 引っ張って更新

主要リスト/ダッシュボード では、プラットフォーム・ネイティブな「引っ張って更新」を利用可能とします。画面ごとの更新アクションの置き場所は [`screen_spec.md`](./screen_spec.md) を正本とします。

## リフレッシュ・フィードバック

リフレッシュ中は、`更新中...` またはプラットフォーム・ネイティブなインジケータを表示します。

## 既存データでリフレッシュ

既存データがある場合、既存データと更新中インジケータを同時に出します。画面全体を空白/スケルトンに置き換えません。

## ロードの状態

ロードの状態は、下記を区別します。

* 初期ロード
* 更新中
* バックグラウンド更新中

## スケルトン

スケルトン UI は、必要な箇所にのみ利用します。過度なスケルトン・アニメーションを使用しません。ロード・インジケータも必要な範囲にのみ表示します。

## 「空」の状態

「空」の状態には、下記を含めます。

* 起きたこと
* ユーザーができること
* 対処アクション

例:

```text
お気に入りパッケージなし

パッケージを追加して、追跡を開始してください。

[パッケージを追加]
```

統計の履歴不足も同じ型とします。文言例: `過去データが不十分`。不足の意味は [`statistics_spec.md`](./statistics_spec.md) / [`domain_rules.md`](./domain_rules.md) を正本とします。

## エラー状態

エラー UI では、下記を提供します。

* 起きたこと
* リトライ
* 別の対処アクション

画面に出す原因は、短い人間可読な文です。HTTP ステータスコードそのものは出しません。

## 部分失敗

プロバイダ単位で、失敗を表示します。ダッシュボード全体をエラーにしません。

```text
Packagist: ✓

GitHub: ⚠ ロードできません
[リトライ]
```

## オフライン状態

オフライン時は、ローカルデータが存在すれば、表示します。下記のように表示可能とします。

```text
オフライン
最終更新: 2時間前
```

## Stale データ

Stale データは、新鮮データとビジュアル的に区別可能とします。

## 無認可の状態

権限不足時に何を要求するかは [`authentication_spec.md`](./authentication_spec.md) を正本とします。
本仕様は、「不足を0として表示せず、`GitHub トラフィック: リポジトリへのアクセス権が必要です` 等の状態として示す」ことのみを定めます。

## 認証 UI

認証方針と UI に出してよい状態は [`authentication_spec.md`](./authentication_spec.md)、設定の画面構成は [`screen_spec.md`](./screen_spec.md) を正本とします。
本仕様は、「認証 UI を統計 UI と分離する」ことのみを定めます。

## クレデンシャル (資格情報) UI

生の Token を UI 状態に置かないこと、および UI に出してよい状態は [`authentication_spec.md`](./authentication_spec.md) を正本とします。
マスク表示と漏洩面は [`security_spec.md`](./security_spec.md) を正本とします。

## 破壊的なアクション

データ削除など不可逆操作には、確認 UI を使用します。

例:

```text
すべてのローカルデータを削除しますか ?

この操作は元に戻せません。

[キャンセル] [削除]
```

## アクセシビリティ

アクセシビリティは、全 UI で考慮します。

対象:

* VoiceOver
* ダイナミック・タイプ
* 視差効果を減らす
* コントラストを上げる
* コントロールを切り替える
* TalkBack
* キーボード
* ポインタ (カーソル)

## 操作領域

到達可能なヒットエリアは [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、インタラクティブ・コントロールの最小サイズを定めます。

iOS/iPadOS では、Apple ヒューマン・インターフェース・ガイドライン (HIG) の推奨サイズを基準とします。

Apple は iOS/iPadOS について、デフォルトのコントロール・サイズを44×44pt、最小コントロール・サイズ を28×28pt としています。

(参考: [Accessibility - Apple Developer Documentation](https://developer.apple.com/design/human-interface-guidelines/accessibility))

## 間隔

隣接するインタラクティブ要素は、誤タップを防ぐため、十分な間隔を確保します。

## ダイナミック・タイプ

テキストは、ユーザーが設定したフォントサイズに適応します。大きいテキストでのクリッピング禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とします。

## テキストの省略

長いパッケージ名のレイアウト手段 (改行、省略、アクセシビリティ・ラベル) は [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、「`vendor/very-long-package-name` を識別不能な形に省略せず、詳細では全文を確認できる」ことのみを定めます。

## ローカライズ

対応言語と翻訳対象カテゴリー、日付/数値のビジュアル書式は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「UI 文字列を UI ロジックにハードコーディングしない」「日本語 UI で英語指標名との混在によって、操作不能にしない」ことのみを定めます。

パッケージの識別子 (`vendor/package`) は翻訳しません。

## 右から左 (RTL)

将来的な RTL 対応を阻害しません。リーディング/トレイリングを使用し、左/右に過度に依存しません。

## 色

色の設計 (システムカラー、意味論的な配色、ダークモードの色) は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「色だけでステータスを表現しない (アイコン/テキストを併用する)」ことのみを定めます。

## ダークモード

ライト/ダーク双方のビジュアル・サポートは [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「主要 UI の状態が、両モードで操作可能である」ことのみを定めます。

## モーション

モーションのビジュアル方針は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「アニメーションが状態変更の理解を助け、装飾的アニメーションを使わない」ことのみを定めます。

## 視差効果を減らす

視差効果を減らす設定時には、アニメーションを縮小/無効化可能とします。

## 画面の向きアニメーション

向き変更時の中間レイアウト禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、「向き変更アニメーションが、情報伝達を阻害しない」ことのみを定めます。

## チャート・アニメーション

チャート更新時のアニメーションは、データ変更の理解を妨げない範囲とします。ビジュアル Token は [`design_spec.md`](./design_spec.md) を正本とします。

## Haptics

重要なユーザー・アクションでは、プラットフォーム・ネイティブ Haptic フィードバックを利用可能とします。

過剰な Haptic フィードバックは避けます。

## ポインタ (カーソル)

iPad/Android タブレット等でポインタ (カーソル) インプットをサポートします。

ポインタ (カーソル) Hover 時のフィードバックを、必要に応じて、提供します。

## キーボード

外部キーボード使用時にも、主要ナビゲーションを実行可能とします。

## フォーカス

キーボード/アクセシビリティ・フォーカスは、ビジュアル的に識別可能とします。

## スクロール位置

向き変更時のスクロール位置は [`ui-viewport.md`](./ui-viewport.md)、ナビゲーション後の維持は [`navigation_spec.md`](./navigation_spec.md) を正本とします。

## 状態保存

何を、システム設定 (Configuration) 変更/再起動後に保持するかは [`application_state.md`](./application_state.md) を正本とします。
本仕様は、「保持された状態が、ユーザーに自然に見える」ことのみを定めます。

## ドメイン状態 vs UI 状態

状態の分類は [`application_state.md`](./application_state.md) を正本とします。
本仕様は、「ドメイン・モデルをビューのレンダリングの状態として直接使わない」ことのみを定めます。

## UI の状態機械

画面状態の遷移は [`state_machine.md`](./state_machine.md) を正本とします。
本仕様は、「読込中/読込完了/エラー等をユーザーが区別できる」ことのみを定めます。

## コンテキスト・メニュー

二次的なアクションは、コンテキスト・メニュー等にまとめることができます。

ただし、重要アクションをコンテキスト・メニューのみに隠しません。

## スワイプ・アクション

スワイプ・アクションは、発見可能性が低いアクションに使用しません。

## 破壊的なスワイプ

削除等の破壊的なアクションを、スワイプだけに依存しません。

## プル・ジェスチャ

「引っ張って更新」と水平スクロール等のジェスチャ・コンフリクトを避けます。

## スクリーンショット・テスト

何をテストするかは [`testing_spec.md`](./testing_spec.md)、Viewport 組み合わせは [`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様は、「主要画面のビジュアル・リグレッションの検出を可能とする」ことのみを定めます。

## アクセシビリティ・テスト

検証項目は [`testing_spec.md`](./testing_spec.md) を正本とします。
本仕様は、「VoiceOver/TalkBack / ダイナミック・タイプ / 視差効果を減らす / キーボード / ポインタを操作可能にする」ことのみを定めます。

## UI パフォーマンス

大量パッケージ/スナップショットを表示しても、スクロール/ナビゲーションが不自然に遅延しないこと。検証対象は [`testing_spec.md`](./testing_spec.md) を正本とします。

## 遅延レンダリング

大量コレクションでは、プラットフォームの遅延リスト/遅延グリッド等を利用します。

全パッケージを一度にレンダリングしません。

## チャートデータ・ロード

長期間のスナップショットを一度に UI に渡しません。期間指定のクエリーは [`storage_spec.md`](./storage_spec.md)、選択できる期間は [`screen_spec.md`](./screen_spec.md) を正本とします。

## 大量のデータセット

UI はパッケージ/スナップショットが増えてもスクロール可能であること。保持上限とクォータは [`storage_spec.md`](./storage_spec.md)、キャッシュ容量は [`cache_spec.md`](./cache_spec.md)、パフォーマンス検証は [`testing_spec.md`](./testing_spec.md) を正本とします。

## ネットワークの独立性

データの流れと層境界は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「ビューがネットワーク状態を直接判定しない」ことのみを定めます。

## エラー・メッセージ

技術的なエラーをそのままユーザーに表示しません。たとえば、下記は、`URLError(-1009)` ではなく、メッセージにマッピングしたものです。

```text
接続できません。
ネットワーク接続を確認してから、もう一度お試しください。
```

## リトライ

リトライ可能なエラーでは、ユーザーが明示的に再試行できます。リカバリー手段は、リトライ/Back/リフレッシュ等とし、エラー UI の型 (起きたこと / 別の対処アクション) は [エラー状態](#エラー状態) を正本とします。

## レート制限

API レート制限到達時は、下記のユーザー向けメッセージを使用します。

```text
リクエストが多すぎます。
後ほど再度お試しください。
```

## データ鮮度

新鮮/Stale の判定は [`cache_spec.md`](./cache_spec.md)、指標ごとの鮮度の意味は [`statistics_spec.md`](./statistics_spec.md) を正本とします。
本仕様は、「`ついさっき更新されました` / `5分前に更新されました` / `昨日更新されました` 等の表示文言」だけを定めます。

## ソースの透明性

ソースの意味は [`statistics_spec.md`](./statistics_spec.md) を正本とします。
本仕様は、「`Packagist` / `GitHub` / `Collected by S2J Package Dashboard` 等を確認できる」ことのみを定めます。

## 偽の精度なし

取得できない精度を UI 上で推測しません。「欠測を0にしない」「Stale を新鮮に見せない」ことは [`domain_rules.md`](./domain_rules.md) / [`cache_spec.md`](./cache_spec.md) を正本とします。

## アクセシビリティ・ラベル

アイコンのみのアクションには、下記のようにアクセシビリティ・ラベルを設定します。

* お気に入り
* リフレッシュ
* リポジトリを開く
* その他

## 意味的グルーピング

関連する指標をアクセシビリティ・ツリー上でも意味的にグルーピングします。

## VoiceOver/TalkBack 順序

読み取り順序は、ビジュアルのヒエラルキーと、可能な限り、一致させます。

## チャートのアクセシビリティ

チャートには、可能な限り、テキスト要約を提供します。傾向を含める場合の意味は [`statistics_spec.md`](./statistics_spec.md) を正本とします。

例: `ダウンロード数 120,000。出典: Packagist.`

## コントラスト

コントラストのビジュアル基準は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「テキスト/アイコン/チャートが、ライト/ダーク双方で読み取れる」ことのみを定めます。

## ローカライズ・テスト

検証する言語は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様のテストでは、「両言語で、主要操作が完了できる」ことだけを確認します。

## 日付のローカライズ

日付/数値のビジュアル書式は [`design_spec.md`](./design_spec.md) を正本とします。
永続化の UTC は [`storage_spec.md`](./storage_spec.md) を正本とします。

## 外部リンク

パッケージ詳細に出す「Packagist を開く」「GitHub を開く」は [`screen_spec.md`](./screen_spec.md) を正本とします。
受信ディープリンクの検証は [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「外部 URL をプラットフォーム標準のブラウザー/Web ビューの方針で開く」ことのみを定めます。

## プライバシー

UI では、不要な個人情報を表示しません。Token/クレデンシャル (資格情報) を通常 UI やエラー・メッセージに出さないことは [`security_spec.md`](./security_spec.md) / [`authentication_spec.md`](./authentication_spec.md) を正本とします。

## デザイン・システム

ビジュアル Token (色、タイポグラフィ、間隔、形状、図像学、高低差) は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「横断 UI がそのデザイン・システムに従う」ことのみを定めます。

## プラットフォーム・ネイティブ・コンポーネント

初期バージョンの UI は、SwiftUI のみです。Android 版の開発に着手したタイミングで、「iOS/iPadOS: SwiftUI」と「Android: Jetpack Compose」に分け、それぞれのネイティブ・コンポーネントを利用します。時期は [`overview.md`](./overview.md) を正本とします。

## プラットフォーム横断型の一貫性

iOS/Android で、情報アーキテクチャー/用語/ドメイン意味/インタラクション・インテントは、可能な限り、統一します。画面の目的は [`screen_spec.md`](./screen_spec.md)、遷移先/経路は [`navigation_spec.md`](./navigation_spec.md) を正本とします。

## プラットフォームの違い

ナビゲーション・コンテナ/Back/サイドバー等の Chrome は [`navigation_spec.md`](./navigation_spec.md) を正本とします。
本仕様は、「コンテキスト・メニュー/シート/システム・ダイアログ/キーボード/アクセシビリティが、プラットフォーム・ネイティブ UX でよい」ことのみを定めます。

## ピクセル・パーフェクト要件なし

ビジュアルの非同一化は [`design_spec.md`](./design_spec.md) を正本とします。
本仕様は、「意味/情報/UX 目標をそろえ、ピクセル単位での一致を要求しない」ことのみを定めます。

## SwiftUI

SwiftUI では、ビューを、可能な限り、プレゼンテーション状態にバインドします。

## Jetpack Compose

Android 版の開発に着手したタイミングで、Compose を使います。初期バージョンの UI は、SwiftUI のみです。時期は [`overview.md`](./overview.md) を正本とします。

Compose では、状態ホイスティングを基本とします。

Android 公式のアダプティブ UI ガイダンスでも、ウィンドウサイズ・クラス等の状態を含む、状態を適切にホイストすることが推奨されています。

(参考: [Canonical layouts | Adaptive Apps - Android Developers](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts))

## 共有 UI ロジック

共有対象は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「SwiftUI ビュー/ Compose コンポーザブルを初期の共有対象にせず、プレゼンテーション状態とインテントをビューから分離する」ことのみを定めます。

## UI アーキテクチャー

層の境界は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「ビューがユースケース/ドメインを直接呼び出さない」ことのみを定めます。

## UI 状態の所有権

状態の分類と信頼できる唯一の情報源 (SSoT) は [`application_state.md`](./application_state.md) を正本とします。
不変な値として扱うことは [`architecture.md`](./architecture.md) を正本とします。

## イベント・ハンドリング

一度きりの操作は [`application_state.md` 単発イベント](./application_state.md#単発イベント) を正本とします。
本仕様は、「タップ/リフレッシュ/選択を、ビューからインテントとして渡す」ことのみを定めます。

## 副作用

ネットワーク/ストレージ/認証等の副作用を、ビューに直接記述しません。

## アニメーション・タイミング

アニメーション継続時間は [`design_spec.md`](./design_spec.md) のデザイン・システムに従います。プラットフォーム標準アニメーションを、可能な限り、利用します。

## スタートアップ Flash なし

起動時および向き変更時の中間レイアウト禁止は [`ui-viewport.md`](./ui-viewport.md) を正本とします。

## 起動の状態

起動時に何を復元するかは [`application_state.md`](./application_state.md) を正本とします。

## バックグラウンド Return

フォアグラウンド復帰時の鮮度チェック/リフレッシュ可否は [`cache_spec.md`](./cache_spec.md) を正本とします。
本仕様は、「復帰時に、既存表示を消して空白にしない」ことのみを定めます。

## メモリ・プレッシャー

メモリ・キャッシュの解放は [`cache_spec.md`](./cache_spec.md)、履歴スナップショットの保持は [`storage_spec.md`](./storage_spec.md) を正本とします。
本仕様は、「チャートの再描画用データを捨てたとしても、履歴が見えなくならない」ことのみを定めます。

## UX 原則

空/エラーで「起きたこと/ユーザーができること」を示すことは [「空」の状態](#空の状態) / [エラー状態](#エラー状態) を正本とします。
本節は、「ユーザーが次の操作を選べない画面を作らない」ことのみを定めます。

## ユーザー・コントロール

自動アクションよりも、ユーザーが明示的に理解できる操作を優先します。

## パフォーマンス vs 精度

指標の意味は [`statistics_spec.md`](./statistics_spec.md) を正本とします。
ロードを短くするために意味を変えません。キャッシュ表示時の鮮度の見え方は [データ鮮度](#データ鮮度) を正本とします。

## UX 非ゴール

下記を、初期バージョンの目標としません。

* 過剰なアニメーション
* ゲーミフィケーション
* ソーシャル機能
* ダッシュボードの、自由度の高いカスタマイズ
* 複雑なジェスチャ・システム
* ピクセル・パーフェクトなプラットフォーム横断型 UI ([ピクセル・パーフェクト要件なし](#ピクセルパーフェクト要件なし))
