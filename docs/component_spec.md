# S2J Package Dashboard - コンポーネント仕様

## 概要

本ドキュメントは、S2J Package Dashboard の初期設計における、コンポーネント・アーキテクチャーを定義します。

UI/UX 仕様、Kotlin Multiplatform (KMP) 構成、ドメイン・モデル、統計、ストレージ、キャッシュ、認証およびプラットフォーム連携の設計進展に応じて、更新します。

## 目的

本ドキュメントでは、UI/プレゼンテーション/ドメイン/プラットフォーム・コンポーネントの分類、責務、依存関係および再利用方針を定義します。

目的は、責務を分離し、ネイティブ UX を維持しながら、共通ロジックを Kotlin Multiplatform (KMP) に移行可能なコンポーネント構造を実現することです。

## 非目的

本仕様では、下記を必須としません。

* 全 UI コンポーネントの Kotlin Multiplatform (KMP) 化
* Compose Multiplatform (CMP) による UI 共有
* 全コンポーネントの独立パッケージ化
* UI コンポーネントからの API 直接呼び出し
* UI コンポーネントによる、永続化ストレージ管理
* UI コンポーネントによる、クレデンシャル (資格情報) 管理
* コンポーネント単位での独立バージョン管理
* コンポーネント単位での外部公開

## コンポーネントの定義

コンポーネントとは、「アプリケーションを構成する責務が明確な、独立した再利用可能なソフトウェア・ユニット」と定義します。コンポーネントには、下記を含みます。

* ドメイン・コンポーネント
* アプリケーション・コンポーネント
* プレゼンテーション・コンポーネント
* UI コンポーネント
* プラットフォーム・コンポーネント
* 基盤コンポーネント

## コンポーネントの基本原則

コンポーネントは、下記を原則とします。

1. 単一の責務を維持する
2. 明確な公開インターフェースを持つ
3. 不要なプラットフォームの依存関係を持たない
4. UI コンポーネントとドメイン・ロジックを混在させない
5. Kotlin Multiplatform (KMP) 共有ロジックへの移行可能性を考慮する
6. プラットフォーム固有のコンポーネントを無理に共有しない
7. コンポーネント間の依存方向を一方向にする
8. 循環した依存関係を禁止する
9. UI コンポーネントはネイティブ UX を尊重する
10. コンポーネント単位でテスト可能とする

コンポーネントを下記の層に分類します。

* ドメイン
* アプリケーション
* プレゼンテーション
* UI
* プラットフォーム
* 基盤

* `PackageRow`
* `StatisticsChart`
* `PackageDetailView`
* `RefreshPackage`

下記のような、過度に汎用の名前を避けます。

* Manager
* Helper
* Util
* Common
* Data
* Thing

### ビューの命名

SwiftUI では、原則として、ビューのコンポーネントには、`...View` を利用します。

### Compose の命名

Compose では、コンポーザブル関数名を UI の意味に合わせます。

### ViewModel の命名

`...ViewModel` を基本とします。

### ユースケースの命名

ユースケースは `Verb + Object` を基本とします。

例:

* `RefreshPackage`
* `AddFavorite`
* `CaptureSnapshot`

* `PackageCard`
* `MetricCard`
* `StatisticsChart`

## コンポーネントのセマンティクス

コンポーネント名・構造は、ビジュアルな見た目ではなく、セマンティックな役割を優先します。

## 汎用カード

単に、CardView という名前だけで、機能コンポーネントを表現しません。

必要に応じて、下記とします。

* PackageCard
* MetricCard
* RepositoryCard

## アクセシビリティ・ツリー

コンポーネント・ヒエラルキーが、アクセシビリティ・ツリーとしても意味のある構造になるよう設計します。

## コンポーネントのテスト・マトリックス

検証の種類は、[`testing_spec.md`](./testing_spec.md) を正本とします。
本仕様は、「コンポーネントが、通常/ロード/空/エラー/Stale/長文/巨大な数/ダイナミック・タイプ/横置き/アクセシビリティを検討対象とする」ことのみを定めます。

## UI リグレッション検出

既存コンポーネントを変更した場合、主要スクリーンのビジュアル・リグレッションを確認します。

## デバイス・リグレッション検出

対象デバイスは、[`ui-viewport.md` の基準端末](./ui-viewport.md#基準端末) を正本とします。

## Viewport リグレッション検出

縦置き/横置き、および、オーバーフロー/到達可能性の確認は、[`ui-viewport.md`](./ui-viewport.md) を正本とします。
本仕様のリグレッション検出では、「コンポーネント単体の表示」を確認します。

## コンポーネントのアクセシビリティ

ラベル、値、ヒントは、[`ui.md`](./ui.md) を正本とします。
本仕様は、「コンポーネントがビジュアル的だけでなく、意味的な情報を持つ」ことのみを定めます。

## コンポーネント状態復元

復元する状態は、[`application_state.md`](./application_state.md) を正本とします。
本仕様は、「ナビゲーション/向き変更後に、コンポーネントが表示用状態を失わない」ことのみを定めます。

## コンポーネントの永続化

永続化は、[`storage_spec.md`](./storage_spec.md) を正本とします。
本仕様は、「UI コンポーネントが、永続化ストレージを直接管理しない」ことのみを定めます。

## 状態復元の境界

復元する状態は、[`application_state.md`](./application_state.md) を正本とします。
本仕様は、「復元をアプリケーション/プレゼンテーション層で管理する」ことのみを定めます。

## コンポーネント・ライフサイクルの境界

コンポーネント・ライフサイクルとデータのライフサイクルを分離します。ネットワーク・リクエストを UI ライフサイクルに直接結合しないことは、[リソース・ライフサイクル](#リソースライフサイクル) を正本とします。

## ネットワーク・ライフサイクル

[リソース・ライフサイクル](#リソースライフサイクル) を正本とします。

## コンポーネント・エラーの分離

一つの機能コンポーネントのエラーが、他機能の UI を不必要に破壊しません。

## コンポーネントのロードの分離

一つのコンポーネントのロードが、スクリーン全体をブロックしない構造を、可能な範囲で、採用します。

## コンポーネントと Kotlin Multiplatform (KMP) 境界

ロジック、プレゼンテーション、UI の置き場所は [`architecture.md`](./architecture.md) / [`kmp_spec.md`](./kmp_spec.md) を正本とします。
本仕様は、ネイティブ UI コンポーネントとプレゼンテーション・コンポーネントの境界だけを定めます。

## 移行候補

Kotlin Multiplatform (KMP) 移行候補は [`architecture.md`](./architecture.md) / [`kmp_spec.md`](./kmp_spec.md) を正本とします。
本仕様は、「プレゼンテーション/ネイティブ UI コンポーネントを、共有対象にしない」ことのみを定めます。

## 非移行候補

Kotlin Multiplatform (KMP) に移行しない対象は、[`kmp_spec.md`](./kmp_spec.md) を正本とします。
本仕様は、「ネイティブ UI コンポーネントを、プラットフォーム内再利用とする」ことのみを定めます。

## ネイティブ・コンポーネントの再利用

ネイティブ・コンポーネントは、そのプラットフォーム内での再利用を優先します。

## プラットフォーム横断型セマンティック再利用

プラットフォーム横断型で共有する必要があるものは、UI コンポーネントではなく、ドメイン/アプリケーションのセマンティクスを優先して共有します。

## 最終的なコンポーネント・アーキテクチャー

層とネイティブ UI の置き場所は、[`architecture.md`](./architecture.md) を正本とします。
本仕様は、「その置き場所に合わせて、コンポーネント境界を切る」ことのみを定めます。

## 最終原則

責務の置き場所は [`architecture.md`](./architecture.md) を正本とします。
本仕様は、「コンポーネント境界を、その置き場所に合わせて切る」ことのみを定めます。
既存 [S2J About Window](https://github.com/stein2nd/s2j-about-window) / [S2J Source List](https://github.com/stein2nd/s2j-source-list) の再利用は、[既存コンポーネントの再利用](#既存コンポーネントの再利用) を正本とします。
